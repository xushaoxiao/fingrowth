# FinGrowth v0.1.0 release preparation

Status: candidate preparation; no tag or GitHub release is created by the build command. The acceptance report in `evals/` is the behavior evidence for this candidate, separate from CI arithmetic and packaging checks.

## Proposed release description

FinGrowth is an independent open-source skill pack for consumer lending growth. It connects engineering, product, growth, risk and finance through five workflows:

- Design a growth architecture with event ownership, failure recovery and a delivery backlog.
- Define a metric tree with explicit populations, loss basis and risk-adjusted contribution.
- Diagnose a nested cohort funnel with reproducible calculations and falsifiable investigation plans.
- Design an experiment with assignment, ITT analysis, power requirements, numeric guardrails and delayed-risk review.
- Adapt a reviewed aggregate source to the dashboard with explicit mappings and provenance.

The Next.js + HeroUI dashboard provides six connected views, browser-local workspace import/export and Default plus seven technology-company inspired themes.

All public examples use invented aggregate data. The included case shows why lower funded CAC need not create more contribution. It demonstrates the framework; it does not establish real-world growth uplift or employer results.

The funnel calculator uses Python 3.10+ and the standard library. The other skills are Markdown workflows with supporting references or assets. Install a whole skill folder and its resources according to your host's supported skill mechanism, or explicitly ask an agent to read its SKILL.md. Explicitly loaded isolated-agent tasks are evaluated; automatic discovery and broad host compatibility are not certified.

## Candidate artifacts

Run from a clean committed Git checkout with Python 3.10+ and Node.js 20.9+ / npm:

```sh
python3 -m unittest discover -s tests -v
python3 scripts/build_release.py --include-dashboard --output dist/v0.1.0
```

With `--include-dashboard`, the command installs locked npm dependencies, type-checks, runs browser-engine calculation tests, builds Next.js and packages the static export. Without that flag it packages source and five Skills only. The output directory must be new or empty. The build reads one pinned committed source snapshot, uses fixed ZIP ordering/timestamps, excludes untracked and ignored files, and embeds the MIT license in each skill folder. Repeatability is checked within the same runtime/compression implementation; no cross-runtime byte identity is promised.

Artifacts:

- `fingrowth-0.1.0.zip`: complete committed source, examples, docs, tests and acceptance records.
- `fintech-growth-architect-0.1.0.zip`
- `growth-metric-tree-0.1.0.zip`
- `growth-funnel-diagnosis-0.1.0.zip`
- `growth-experiment-design-0.1.0.zip`
- `growth-data-adapter-0.1.0.zip`
- `fingrowth-dashboard-0.1.0.zip`: optional checked static export, built with `--include-dashboard`.
- `manifest.json`: exact source commit/tree, filenames, sizes and SHA-256 values.
- `SHA256SUMS`: all ZIPs plus the manifest.

The source ZIP supports demo execution but omits `.git`; rebuilding a release requires the Git checkout. Skill ZIPs extract to a single named skill folder including its license. Check that the manifest's source is the reviewed commit; do not reuse an older candidate after modifying or merging source.

## Publishing handoff

Before publication, confirm the final acceptance record and CI correspond to the reviewed source, select/merge the final commit, rebuild from that clean commit, verify checksums and run the extracted source demo plus extracted funnel skill. Only then create the `v0.1.0` tag/release with the reviewed description and upload the exact artifacts and checksums. Merging can change the source commit, so rebuild rather than relabeling old candidates. This document prepares that handoff; it does not record a publication.

## Known limits

- Maturity is declared in the synthetic fixture, not derived from contractual schedules or exposure-level observation.
- Cohorts must be nested unique first-loan people; independent monthly events or overlapping loan exposures require a different aggregation/model.
- Currency syntax is checked, but there is no registry validation or FX conversion.
- No causal channel winner, lifetime value, default probability or legal suitability is inferred.
- The experiment skill can explicitly leave power/sample size unresolved; no bundled power calculator exists.
- Agent acceptance covers the committed tasks in the session environment. It is not a guarantee across models, prompts, host discovery mechanisms or live business systems.
- Feishu synchronization and production business-path acceptance have not been performed.
