# KYC 上传指导实验卡

状态：**blocked before launch**。样本量计算已实际执行，但风险/投诉数值阈值、暴露上限及具名审批尚未提供；不能因此启动实验。

本卡使用任务提供的聚合规划输入：7 日 KYC 完成率基线 60%、绝对 MDE 3 个百分点、按人 1:1、双侧 alpha 0.05、power 0.8、两组合计每天约 400 个符合资格且同意参与的新申请人。基线来源、统计窗口、业务国家和具体产品均未提供，未独立验证。未读取个人数据、雇主材料或生产系统。

## 业务问题与设计

- 业务决策：是否值得扩大“更清晰的资料上传指导”，同时保持原授信、定价、资格与风险政策。
- 假设：对合格新申请人在 KYC 前提供更清晰的上传指导，能提高分配后七日内完成 KYC 的比例。
- 统计假设：`H0: p_treatment − p_control = 0`；双侧备择为差异不为零。规划备择取 `p_control = 0.60`、`p_treatment = 0.63`。
- 资格：尚未接受本次干预、符合既有政策、同意参与的新申请人；具体产品、国家、设备范围及预处理排除条件由业务/隐私负责人确认后冻结。
- 随机化单位：唯一的人，而非设备、会话或重复申请；分配发生在首次干预前。1:1 分配持续保存在分配记录中，跨设备/重试不得重抽；去重标识由获准的内部系统使用，不进入公开实验材料。
- 对照：当前指导；实验：改进后的指导。两版具体素材尚待审阅，除指导外不改变 KYC、授信或定价规则。对照恢复路径必须可用。
- 分配目标：每组至少 4,129 人。预注册能保持平衡的随机分配方式；如果使用可能出现数量不平衡的简单随机分配，实际募集可能延长，不能只凭总量 8,258 判定结束。
- 暴露上限：尚未获批；由实验和风险负责人确定。计划样本量不是获准暴露额度。

## 主指标与分析

主指标采用 ITT：分配后七日内达到预注册的服务器端 KYC 完成终态的唯一人数 / 所有已分配且分配时合格的人数。两组定义、起点、时区和七日边界必须一致。需要确认“完成”是流程完成还是审核通过，并核对 60% 基线使用相同口径。不得改用“已上传”或“已获批”人群作主指标分母；HTTP 202、重复回调或前端点击不代表完成。

主分析在固定读数时间进行一次，报告两组分配人数、完成数、比例差、置信区间和预注册双侧检验。按 assignment 分析，不仅分析实际看到或完成上传的人。失访、撤回同意或数据删除的处理及敏感性分析须在合法数据政策下预注册；不能事后删除不利结局或把未知情况静默填零。分群先作描述性探索；如转为正式多重检验，另行定义调整方法和样本规划。

3 个百分点在这里是**功效计算的规划差异**。本计算在真实差异为 +3 个百分点时，以约 80% power 检验“差异为零”；它不保证观察到 +3 个百分点，也不以 80% 概率证明提升至少达到 +3 个百分点。若业务要求证明效果至少超过 3 个百分点，应另行制定最低效果假设与样本规划，不能沿用当前结论。即便统计显著，仍须评估效果大小、成本与成熟风险。

## 已执行的计算与证据

实际从仓库运行 bundled script，命令退出码为 0；JSON 和 Markdown 输出分别保存在本次评估目录的 `power-plan.json` 与 `power-plan.md`。

```sh
python3 skills/growth-experiment-design/scripts/plan_power.py \
  --baseline 0.60 --mde-absolute 0.03 --alpha 0.05 --power 0.80 \
  --eligible-per-day 400 --primary-followup-days 7
```

| 结果 | 实际输出 |
| --- | ---: |
| 每组样本量 | 4,129 |
| 两组合计 | 8,258 |
| 此样本的近似 power | 0.8000351788374795 |
| 每组少一人的近似 power | 0.7999401560815504 |
| 最小预期成功/失败格数 | 1,527.73 |
| 预计募集天数 | 21 |
| 最后一次分配后的主指标随访 | 7 天 |
| 最早主指标读数 | 启动后第 28 天 |
| 延迟信用风险读数日期 | 未知，需按贷款计划和观察成熟度另定 |

方法为两独立比例 z-test 的 pooled-null / unpooled-alternative 正态近似，以两侧拒绝概率求和并对整数每组人数求最小值。无连续性校正，不是精确二项检验。当前输出的预期格数超过工具的保守范围门槛 10；这不是未来数据质量或有限样本精确性的保证。[工具所用方法参考](https://www.statsmodels.org/v0.14.6/generated/statsmodels.stats.proportion.power_proportions_2indep.html)

募集计算为 `ceil(8258 / 400) = 21`，主指标读数计算为 `21 + 7 = 28`。400/日是提供的平均规划假设，若流量波动、分配不平衡、事件延迟或结果缺失，实际日期需延后。这里只是相对启动日的规划，不是已经排期或正在进行的实验。KYC power 不等于对低频欺诈、投诉、信用损失或贡献收益有足够 power。

安全/运营护栏可以按批准程序持续监控；主指标不能每天重复做显著性检验并见好即停。若要序贯决策，应另用有效方法，当前固定周期规划不适用。

经济性指标建议另跟踪成熟贡献 / 所有分配合格人数。需要确认收入、获客、资金、服务、激励与单一损失口径，归属人群和时间一致。当前没有相关数据，也没有对金额均值提供 power 计算。

## 启动前仪表与验收

1. 预演唯一人分配、持久化、跨会话重试和重复申请去重，记录 assignment、版本 exposure、结果终态和时间戳；不把仅获成功的人写入 assignment 表。
2. 检查 1:1 分配平衡和 sample-ratio mismatch、资格误纳、分配后排除、跨组污染及素材版本一致性；出现问题先调查随机化机制，不静默删样本。
3. 对账分配、曝光与完成事件，处理重复回调、缺失和迟到；审阅主指标七日窗口与基线一致性。
4. 完成批准的数值护栏、监控窗口、异常上报和恢复演练；明确唯一 rollback owner 与恢复对照的执行人。
5. 由业务实验、Engineering、Operations/Privacy、Risk/Finance 及适用本地合规负责人具名确认后才可启动。所在司法辖区和适用审阅要求目前未知，不能声称合规已满足。
